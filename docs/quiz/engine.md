# 적응형 엔진 프로토타입

## 현재 범위

실제 문제은행은 중1~중3 각 24문항으로 총 72문항이다. 초6/고1~고3은 아직 없다. `startQuiz`의 기본 범위는 1~7이며 콘텐츠 부족 시 오류를 낸다. 현재 검증에는 `levels: [2, 3, 4]`를 명시한다.

## 출제 정책

- 중2에서 시작해 정답이면 한 단계 상승, 오답/넘기기/시간 초과면 한 단계 하락한다.
- 처음 네 문항은 네 영역을 하나씩 탐색한다.
- 8~10번째 문항은 가장 높은 정답 레벨에서 정답 근거가 부족한 영역을 우선 확인한다. 이 레벨이 최종 확정 학년이라는 뜻은 아니다.
- 동일 ID 재출제는 금지한다. 현재 레벨 안에서 미출제 skill, 직전과 다른 영역, 미출제 family를 우선한다. 후보 부족 시 유형 반복은 허용하지만 레벨을 임의로 바꾸지는 않는다.
- 최근 ID 목록은 최신순이며, 다른 조건이 같은 후보에서는 최근 미출제 문항을 우선한다. 모두 최근 문항이면 오래된 것을 우선한다. 저장은 추후 UI에서 연결한다.
- 현재 실제 은행은 속도 가속을 모두 꺼 두었다. 보정 후 명시적으로 활성화한 문항에서만 1초 이상·문항 기준시간 이내 정답을 두 단계 상승에 사용할 수 있다.

## 최종 학년 근거

높은 레벨부터 확인해 정답 세 개 이상, 서로 다른 정답 영역 세 개 이상, 정답률 75% 이상이면 확정한다. 특정 레벨의 분모는 그 레벨 응답 및 상위 정답이다. 상위 오답은 하위 지식의 부정 근거로 사용하지 않는다. 모든 확정 조건이 부족하면 지원 범위의 최저 학년을 provisional로 반환한다. 하한 표시는 숙달 확인이 아니다.

이는 재미용 정책이며 통계적으로 보정된 능력 추정 모델은 아니다. 추후 플레이에서 반복되는 과대/과소 판정이 확인되면 정책을 조정한다.

## API 및 타이머

`startQuiz(bank, options)`는 첫 pending 문항을 돌려준다. `submitAnswer(bank, state, answer, elapsedMs, options)`는 기존 state를 변경하지 않고 다음 상태를 돌려준다. answer는 0~3 또는 skip/timeout이다. 20,000ms 이상 응답은 정답을 골라도 timeout이다. 열 번째 응답 이후 pending은 null이고 result가 존재한다.

UI는 시간 측정에 단조 증가하는 시계를 사용하고, 동일 상태에 대한 중복 클릭을 차단해야 한다. 보기 섞기는 `shuffleChoices`가 정답 인덱스도 함께 바꾼다. 섞인 pending 문항을 상태에 보관해야 표시 보기와 채점 인덱스가 일치한다.

## 검증 결과

- 72문항/36슬롯, 슬롯당 2문항과 영역당 6문항 검증
- 1,024개 정오답 경로 × 8개 난수 시드, 총 8,192회차 검증
- 11개 테스트: 종료/초반 네 영역/문항 중복/실수 후 회복/하한/영역 편중/타이머/유효성/보기 섞기/속도/최근 기록
- 합성 7레벨 은행으로 고3까지 도달 가능성을 확인했다. 고등학교 실제 문항 난이도 검증은 아니다.
- Node 24의 타입 제거 기능으로 실행 검증했으며 별도 정적 TypeScript 검사는 아직 구성하지 않았다.
